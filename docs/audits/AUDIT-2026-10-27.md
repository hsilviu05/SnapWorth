## 2. Findings

### [Medium] M1. PR #403: neither privacy policy mentions typed descriptions

- **Evidence:** both policies say what is collected, and only photos are named as input. Neither was touched by the PR:
  - `backend/main.py` `/privacy`: "We collect photos you submit for valuation or for a legit check…"
  - `ios/SnapWorth/Views/Settings/LegalView.swift`
- With #403, free text the user types goes to the server and to Gemini. The item name derived from it also reaches the operator feed, `/trends` and the notable-finds list.
- `PrivacyInfo.xcprivacy` and the App Store Connect App Privacy answers declare Photos, but not Other User Content.
- **Risk:** under Guideline 5.1.1(i), the policy must say what data the app collects and how it is used. A reviewer who tries the new button and reads the policy can reject the build for that.
- **Fix:**
  - Add one sentence to both policies: typed descriptions are sent to the AI model in the same way as photos, and are not stored.
  - Add `NSPrivacyCollectedDataTypeOtherUserContent` (not linked, App Functionality) to the app's privacy manifest.
  - Update the App Privacy label in App Store Connect to match.
  - New policy text is a user-facing string, so it needs entries in all five languages in `App.json`.

### [Low] L1. The `<untrusted_data>` fence can be closed early

- **Evidence:** `promptsafety.fence` (`backend/scan/promptsafety.py`) removes `</untrusted_data>` in one case-sensitive pass. I ran it. These inputs all come out with a working closing tag inside the fenced value:
  - `</untrusted_</untrusted_data>data>` becomes `</untrusted_data>`;
  - `</UNTRUSTED_DATA>`;
  - `</untrusted_data >`.
- **Why it matters more now:** until #403, a fenced value was model output or an operator hint. `/scan/text` fences the user's own text and puts it straight into the scan prompt.
- **Impact is contained:**
  - The server caps a typed result's confidence.
  - Prices are clamped to the category band.
  - The reply is validated against the schema.
  - An injected scan is seen only by the person who typed it.
  - The second hop is the weekly social-ideas prompt (`insights/ideas.py`), which only drafts text for the operator.
- **Fix:** strip case-insensitively and repeat until nothing changes, or simply escape `<` and `>` in the value before fencing. Add the three strings above as tests.

### [Low] L2. PR #403: typed scans feed `/trends` and the notable-finds list

- **Evidence:** `/scan/text` ends in `_deliver_scan(..., reread=False)`, and from there `notify.scan_completed` tallies the result into trends exactly as a photo scan does.
- **Why it matters:** a typed item is something someone thought of, not something seen in a thrift store. Typing also makes it easy to push a chosen brand or name. The device thresholds (2 devices per category, 3 per brand or find) still apply, so this is a data-quality issue rather than an exploit.
- **Fix (product call):** tally typed scans separately, or skip the trends tally for them. They can still be counted as scans and costs.

### [Low] L3. PR #403: a typed scan can get error messages about photos

- **Evidence:** `/scan/text` shares `_analyse`, so:
  - a safety block answers "This photo couldn't be analysed. Try a clear photo of a single item.";
  - a not-resalable item answers "…Try a photo of a single item you'd actually sell."
- **Fix:** pass a flag into `_analyse` / `_not_resalable_message` so a description gets wording like "Try describing a single item you'd sell."

### [Low] L4. The Telegram admin bot checks which chat a message came from, not who sent it

- **Evidence:** `ops/notify.py` `_handle_update` accepts any message or button press whose `chat.id` equals `TELEGRAM_CHAT_ID`. It never reads `from.id`. The code also follows a group-to-supergroup migration (`ops/telegram.py`, `migrate_to_chat_id`), so a group chat is a supported setup.
- **Impact:** in a private chat, none. In a group, every member has the full operator console: `/clear`, levers such as free-scan and paywall switches, `/sub` lookups, test scans that spend Gemini credit, and referral switches.
- **Fix:** add a `TELEGRAM_OPERATOR_IDS` allowlist and require `from.id` to be on it, for both messages and button presses.
- **Question for you:** is `TELEGRAM_CHAT_ID` your private chat with the bot, or a group?

### [Low] L5. CI hygiene

- `backend.yml`, `ios.yml`, `eval.yml`, `secrets.yml` and `website.yml` declare no `permissions:`, so their token gets the repository's default access. Add `permissions: { contents: read }` at the top of each, and check that Settings → Actions → Workflow permissions is set to "Read repository contents".
- Actions are pinned by tag (`@v7`), not by commit SHA. All of them are first-party `actions/*`, so the risk is low. Pinning by SHA is the stricter option if you want it, and Dependabot can keep SHA pins current.
- `zizmor` also flags `persist-credentials` (the default `true`) on checkout. No job uploads the checkout as an artifact, so this is informational only.
- What is already right: no `pull_request_target`, secrets are only used on pushes to `main` or same-repo runs, the Railway CLI version is pinned, and the secret scan runs on every branch.

### [Info] I1. The website sends no Content-Security-Policy

- `website/vercel.json` sets nosniff, Referrer-Policy, X-Frame-Options and Permissions-Policy, but no CSP. Vercel adds HSTS on its own (medium confidence; I could not fetch the live headers from here).
- The site is static, and the one page that reads the URL (`invite.html`) filters the code to A–Z and 0–9 and sets it with `textContent`. Every `innerHTML` use I found renders data from the page itself.
- A CSP would be defence in depth only. If you add one, it has to allow Vercel Analytics' `/_vercel/insights/script.js` and the pages' inline scripts.

## 3. What was reviewed and found clean

- **New endpoints since 10-11:**
  - `/legit` and `/rack` refuse non-Pro callers before reading any photo, validate the image bytes, and are rate-limited and covered by the safety-block pause.
  - `/legit`'s brand and item fields are sanitised and fenced (see L1 for the fence itself).
- **Request size:** `LimitRequestBody` (pure ASGI) caps every body, and `_read_capped` caps each upload part.
- **Shared sales (`/outcomes`):** an edit or delete by another install gets a 403, and the daily cap is counted per attested caller.
- **Refunds:** the tombstone lock (#398) uses `add` with a token and releases only its own lock, and it is `required` so it cannot fall back to one process's memory.
- **TikTok callback:** rate-limited, and returns fixed HTML with no reflected input.
- **Operator feed:** every user-derived string I traced into Telegram's HTML mode goes through `html.escape`.
- **`/metrics`:** behind a bearer token, and 404 when `METRICS_TOKEN` is unset.
- **CORS:** off unless `ALLOWED_ORIGINS` is set.
- **TypeSafe (Jev):** off by default, and disclosed in both privacy policies.
- **iOS:**
  - Tokens are in the Keychain with `AfterFirstUnlockThisDeviceOnly`.
  - No ATS exceptions, and every API call goes to `https://api.snapworth.eu`.
  - No `print` or `NSLog` in shipping code; the one `Logger.debug` logs counts only.
  - `MockPurchaseService` is used only in SwiftUI previews.
  - Purpose strings exist for camera, photo library and photo-library add.
  - The privacy manifests declare UserDefaults (CA92.1, 1C8F.1) and file timestamps (C617.1). The one file-timestamp call is in `StoreProtection.swift`.
- **PR #403's iOS code:** no analytics event or log line carries the typed text.

## 5. Second pass: deeper review of the backend and the Swift app

After the fixes above, one reviewer read the production backend and the Swift app in full, against this file and the earlier audits. It reported nine candidates. Each was checked against the code here, and four were also reproduced by running it: N1, N6, N5 (a mutation-checked test) and N9.

Nothing is Critical or High. All nine are fixed in the same PR.

| # | Sev | Finding | Fix |
|---|---|---|---|
| N1 | Medium | `/scan/text` cut the end off descriptions. `_clean_description` capped `sanitize_text` at `len(raw)+1`, but NFKC lengthens text. Running it, "size 10½" reached the model as "size 101⁄", so the wrong size was priced and a free scan was spent. | No truncation. The 200 cap is measured before NFKC, counting characters as the phone does. A fraction after a digit gets a space, so it reads "10 1⁄2". |
| N2 | Low | "Add a photo instead" started the library scan while the Type it sheet was still closing. A paywall raised then was dropped, and `showPaywall` stayed true, which kept the camera stopped until relaunch. | The picked photo is held, and handed to the library path in the sheet's `onDismiss`, the same way the typed scan already waits. |
| N3 | Low | Pasting text that contains a line break submitted it at once and spent the free scan. | Only an actual Return submits. Pasted line breaks become spaces. |
| N4 | Low | The app counts the 200 limit as characters a person sees, while the server counted code points after NFKC. Text the app allowed could be refused in English. | Fixed with N1: the server now counts the same way. |
| N5 | Low | `_is_revoked` read the refund tombstone without `required`. A Redis failure was answered from process memory as "not revoked", the warning never ran, and `_rederive` cached Pro for 24 h. | `required=True`. An unreadable tombstone still grants Pro for that one request, but is not cached. |
| N6 | Low | The fence fix above still let `</untrusted_data x>` and `</untrusted_data/>` through. Reproduced. | The tag pattern now takes anything after the name, and a tag left unclosed at the end. |
| N7 | Low | The Sandbox notification route claimed the idempotency key first and undid it with a non-required delete, the order the production route had already dropped. It also ignored `REFUND_REVERSED`, so #398 had no caller there. | Both routes now share `_apply_refund_change`: the change is stored first and claimed after, and a Sandbox reversal is applied. |
| N8 | Low | "Delete my shared sales" did not account for a share still in flight. If that share landed after the DELETE, it re-created the record under a token the app had just discarded, so the record could never be deleted. | Each completed delete bumps a counter. A share that finishes after one sends a DELETE for its own record under its own token. |
| N9 | Low | `/revenue`'s month currency list and the paywall A/B's currency list were read-modify-write with no lock. Two first payments in different currencies at once dropped one, and with it that currency's money from the totals. Reproduced. | `core.cache.add_to_json_set`, under a short lock taken with `add`. |
