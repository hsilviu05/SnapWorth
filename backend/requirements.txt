# StoreKit 2 signed transactions are ES256 JWS. 2.13.0 closes six advisories,
# including PYSEC-2026-176, a verifier-side algorithm allow-list bypass that
# would in principle be an entitlement-forgery path to free Pro. That one is
# already defeated independently by the explicit `alg != "ES256"` rejection in
# entitlements.py:211, which runs before jwt.decode — the upgrade removes the
# reliance on that single check rather than introducing the protection.
#
# 2.13.0 also clears PYSEC-2025-183 (CVE-2025-45768, "weak encryption"), which
# has no listed fix version. That advisory was disputed on the grounds that key
# length is the caller's choice; 2.13.0 answers it by emitting
# InsecureKeyLengthWarning for HMAC keys under 32 bytes. It never applied here
# in any case — both call sites are ES256 over an EC P-256 key
# (entitlements.py:219 verifies, devicecheck.py:72 signs) and no HMAC key
# exists in production code. No audit allowlist entry is therefore needed.
